DEFECT #1: Command-line Arguments Not Implemented
================================================================================
SEVERITY: High
STATUS: Documentation vs Implementation Mismatch

README DOCUMENTATION:
  "python app.py --host=0.0.0.0 --port=8080"

ACTUAL IMPLEMENTATION:
  Flask app.py doesn't parse --host or --port arguments.
  Default runs on 127.0.0.1:5000

REPRODUCTION STEPS:
  1. Run: python app.py --host=0.0.0.0 --port=8080
  2. Expected: App runs on 0.0.0.0:8080
  3. Actual: Flask app starts with default values, ignoring arguments
     The script treats --host and --port as unknown arguments to Flask's 
     built-in server, which only accepts debug and use_reloader flags.

ERROR TRACE:
  $ python app.py --host=0.0.0.0 --port=8080
  * Serving Flask app 'app'
  * Debug mode: on
  * Running on http://127.0.0.1:5000
  (--host and --port arguments silently ignored)

FIX: Modify app.py to parse command-line arguments:
  if __name__ == '__main__':
      import argparse
      parser = argparse.ArgumentParser()
      parser.add_argument('--host', default='127.0.0.1')
      parser.add_argument('--port', type=int, default=5000)
      args = parser.parse_args()
      app.run(host=args.host, port=args.port, debug=True)

TEST CASE: test_config.py::TestCliArguments::test_app_run_with_default_args

DEFECT #5: Missing API Endpoints
================================================================================
SEVERITY: High
STATUS: Completely Missing Feature

README DOCUMENTATION:
  "API Reference

   - POST `/api/register`
     - Body: `{ "user": "name", "pass": "123", "mail": "email@example.com" }`
     - Response: `201 Created`

   - POST `/api/login`
     - Body: `{ "user": "name", "pass": "123" }`
     - Response: `200 OK`"

ACTUAL IMPLEMENTATION:
  Neither /api/register nor /api/login endpoints exist.
  Both return 404 Not Found.

REPRODUCTION STEPS:
  1. Start app: python app.py
  2. Send POST request: curl -X POST http://localhost:5000/api/register \
       -H "Content-Type: application/json" \
       -d '{"user": "testuser", "pass": "password123", "mail": "test@example.com"}'
  3. Expected: 201 Created response
  4. Actual: 404 Not Found

ERROR TRACE:
  POST /api/register HTTP/1.1" 404 -
  POST /api/login HTTP/1.1" 404 -

TEST CASE: test_auth.py::TestEndpointDiscrepancies::test_api_register_not_found
TEST CASE: test_auth.py::TestEndpointDiscrepancies::test_api_login_not_found

FIX: Implement JSON API endpoints in auth.py or create new api_bp blueprint
  
Example implementation in auth.py:

  @auth_bp.route('/api/register', methods=['POST'])
  def api_register():
      data = request.get_json()
      conn = get_connection(current_app)
      
      if not data or 'user' not in data or 'pass' not in data or 'mail' not in data:
          return {'error': 'Missing required fields'}, 400
      
      existing = User.get_by_username(conn, data['user'])
      if existing:
          conn.close()
          return {'error': 'Username already exists'}, 400
      
      user = User.create(conn, data['user'], data['pass'], data['mail'])
      conn.close()
      
      return {'message': 'User created', 'user_id': user.id}, 201

  @auth_bp.route('/api/login', methods=['POST'])
  def api_login():
      data = request.get_json()
      conn = get_connection(current_app)
      
      if not data or 'user' not in data or 'pass' not in data:
          return {'error': 'Missing credentials'}, 400
      
      user = User.get_by_username(conn, data['user'])
      if not user or not user.verify_password(data['pass']):
          conn.close()
          return {'error': 'Invalid credentials'}, 401
      
      login_user(user)
      conn.close()
      return {'message': 'Login successful', 'user_id': user.id}, 200

DEFECT #8: Redis Session Storage Not Implemented
================================================================================
SEVERITY: Low (Documentation error, not implementation error)
STATUS: Documentation vs Implementation Mismatch

README DOCUMENTATION:
  "Sessions are stored server-side in Redis"

ACTUAL IMPLEMENTATION:
  No Redis integration present.
  Flask-Login uses default session storage (in-memory for development).
  In production with multiple workers, sessions would be lost.

NOTE: This is not necessarily a defect in development but is misleading
documentation. For development, in-memory sessions are fine.

FIX: Either:
  Option A - Update documentation to clarify sessions are in-memory/file-based
  Option B - Implement actual Redis session storage

For Option B, would need:
  - redis Python package
  - flask-session package
  - Redis server running
  - Configuration in app.py
